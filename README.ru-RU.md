# HyperScope

**Лёгкий self-hosted мониторинг на Rust: веб-панель и агент сбора с поддержкой TLS/mTLS.**

[English](README.md) · [中文](README.zh-CN.md) · [Русский](README.ru-RU.md)

![Панель HyperScope](docs/screenshot.jpeg)

HyperScope мониторит несколько Linux- и Windows-машин из одной панели. Репозиторий является Cargo workspace с общей библиотекой core, веб-панелью и агентом `hyper-node`.

| Компонент | Назначение |
|---|---|
| **hyper-panel-core** | Общие модели предметной области, DTO протокола, персистентность, опрос и безопасные сетевые взаимодействия |
| **hyper-scope** | `hyper-node` — бинарный агент сбора данных на отслеживаемых машинах |
| **hyper-panel** | Веб-панель Axum, REST API, аутентификация и агрегация узлов |

Направление зависимостей: `panel -> core`, `hyper-node -> core`.

---

## Возможности

- **Мониторинг в реальном времени** — CPU, память, температура (включая GPU: NVIDIA/AMD), диск, сеть, процессы, порты, логи по каждому узлу
- **Безопасность по умолчанию**:
  - TLS 1.3 (rustls) с автоматически сгенерированными самоподписанными сертификатами (10 лет)
  - Пиннинг отпечатка сертификата — TOFU при первом подключении, далее фиксировано (защита от MITM)
  - **Взаимный TLS** — каждый узел проверяет клиентский сертификат панели через список доверия
  - Ключи API на узел; `key setup` выводит `ключ|SHA256:отпечаток` — TLS и пиннинг включаются сами
  - HttpOnly cookie, хеши argon2, постоянные сравнения, единый 401 (без перечисления пользователей), лимит попыток входа (5 ошибок / мин блокировка)
- **Многопользовательность** — изоляция узлов по владельцу; админ управляет пользователями; обычные пользователи видят только свои узлы
- **Пул keep-alive соединений** — Пример: 22 узла опрашиваются за ~35 мс в локальной сети с низкой задержкой и keep-alive
- **Удалённая перезагрузка / выключение** — из веб-интерфейса или CLI, через TLS, с диалогом подтверждения
- **Управление Docker-контейнерами** — просмотр, запуск, остановка, перезапуск и удаление контейнеров через веб-панель
- **Проверка протокола** — подключение с обычным ключом к TLS-only серверу отклоняется с понятной причиной
- **Управление узлами (CLI/веб)** — добавление (одиночное/пакетное/из файла), переименование, ping, логи, удаление
- **История событий** — события онлайн/офлайн/аутентификации, сохраняются между перезапусками
- **i18n** — китайский / английский / русский интерфейс
- **Графики в реальном времени** — кривые трафика, история температуры, TOP процессов
- **История** — SQLite-персистентность CPU/память/диск/темп/сеть/TCP (90 дней), агрегация 1ч/24ч/7д/30д, экспорт CSV, следует за выбранным узлом
- **Мобильный UI** — одноколоночная верстка, крупные кнопки

## Быстрый старт

### 1. Установите агент на каждую машину

Одна команда — скрипт определит архитектуру и установит бинарник + systemd-сервис:

```bash
curl -fsSL https://raw.githubusercontent.com/saves24/HyperScope/main/install.sh | sudo bash -s node
```

Затем создайте ключ и запустите сервис:

```bash
sudo hyper-node key setup          # создать ключ API (+ TLS-сертификат для шифрованного режима)
sudo systemctl start hyper-node   # (установщик уже включил сервис)
sudo hyper-node key show          # вывод: <ключ>|SHA256:<отпечаток>
```

> Агент слушает `0.0.0.0:5000`, **по умолчанию TLS-режим** (самоподписанный сертификат
> генерируется при первом запуске). Для внутренних сетей можно переключиться на
> открытый режим: `hyper-node mode plain`.

### 2. Установите панель на сервер

```bash
curl -fsSL https://raw.githubusercontent.com/saves24/HyperScope/main/install.sh | sudo bash -s panel
sudo systemctl start hyper-panel
```

### 3. Войдите и добавьте узлы

Откройте `http://<ваш-сервер>:8088` и войдите с учётной записью администратора по умолчанию:

> **Админ по умолчанию: `admin` / `admin` — сразу смените пароль!**
> `sudo hyper-panel user passwd admin`

Добавьте узел: вставьте адрес (`IP:5000`) и **полный ключ из `hyper-node key show`**
(включая часть `|SHA256:...`). Панель автоматически включит TLS и пиннинг — без лишних шагов.

### Сборщик для Windows

Скачайте `hyper-node-windows-amd64.exe` из Release и запустите в PowerShell:

```powershell
# разовая настройка ключа, затем запуск
.\hyper-node.exe key setup <ваш-ключ>
.\hyper-node.exe serve
```

Конфигурация в `C:\ProgramData\hyper-node` (ключ, mode, сертификат). Метрики через sysinfo, температура через WMI, перезагрузка/выключение через `shutdown /r|/s`.

Скрипты установки и удаления

В репозитории предоставлены скрипты для установки и удаления Windows-агента:

- `deploy/install-windows.bat` — установка Windows-агента как службы
- `deploy/uninstall-windows.bat` — удаление Windows-агента

### Режим обратной отправки (без порта прослушивания)

Узел может работать без открытого входящего порта: он подключается **наружу** к панели и отправляет метрики.

```bash
hyper-node connect http://<панель>:8088 <имя-узла> <ключ-узла>
```

- Основной канал: WebSocket (реальное время, 5 с)
- Запасной: HTTP POST на `/api/push`, если WebSocket недоступен
- Регистрация узла с флагом `--push` (`hyper-panel node add ... --push`) или `"push": true` в API
- Статус/данные узла берутся из кэша панели

## Скрипт установки

Установщик поддерживает две роли:

```bash
# Установка агента (hyper-node) — на каждой отслеживаемой машине
curl -fsSL https://raw.githubusercontent.com/saves24/HyperScope/main/install.sh | sudo bash -s node

# Установка панели (hyper-panel) — на сервере мониторинга
curl -fsSL https://raw.githubusercontent.com/saves24/HyperScope/main/install.sh | sudo bash -s panel
```

Что делает скрипт:
- Определяет архитектуру (`amd64` / `arm64`) и скачивает подходящий бинарник из GitHub Releases
- Устанавливает бинарник в `/usr/local/bin/`
- Создаёт каталоги конфигурации (`/etc/hyper-node`, `/etc/hyper-panel`)
- Устанавливает и включает systemd-сервис (автозапуск при загрузке, перезапуск при сбое)

Ручная установка (без скрипта):

```bash
# агент
sudo cp hyper-node /usr/local/bin/
sudo cp hyper-node.service /etc/systemd/system/
sudo systemctl enable --now hyper-node

# панель
sudo cp hyper-panel /usr/local/bin/
sudo cp hyper-panel.service /etc/systemd/system/
sudo systemctl enable --now hyper-panel
```

## Команды

### Панель CLI (`hyper-panel`)

```text
hyper-panel node add <адрес> <ключ>              добавить узел (порт по умолчанию 5000; пакетно: {адрес ключ}{адрес ключ}...; --tls шифрование)
hyper-panel node link [--tls|--plain] <адрес> <ключ>  подключить узел (--tls шифр. / --plain тест; по умолчанию: авто TLS когда ключ содержит отпечаток)
hyper-panel node add -f <файл>                   импорт узлов из файла (строка "адрес[:порт] ключ")
hyper-panel node rename <имя> <новое>            переименовать узел
hyper-panel node ping <имя>                      проверить доступность узла
hyper-panel node del <имя>                       удалить узел из конфига
hyper-panel node list                            список всех узлов
hyper-panel node show <имя>                      детали узла (включая связь)
hyper-panel setup [--user <имя>]                 сброс администратора (перезаписывает всех пользователей, по умолч. admin, интерактивный пароль)
hyper-panel user add <имя>                       добавить пользователя (интерактивный пароль)
hyper-panel user del <имя>                       удалить пользователя
hyper-panel user passwd <имя>                    сменить пароль (интерактивно)
hyper-panel user rename <старое> <новое>         переименовать пользователя
hyper-panel user list                            список всех пользователей
hyper-panel port [N]                             просмотр / смена порта панели (по умолч. 8088, после рестарта)
hyper-panel log show [N]                         лог панели (последние N строк, по умолч. 50)
hyper-panel log system [N]                       лог systemd (journalctl -u hyper-panel, по умолч. 50)
hyper-panel log retention <дней>                 срок хранения логов (по умолч. 7)
hyper-panel serve [--port N]                     запустить агрегатор (по умолч. 8088)
hyper-panel help                                 справка
```

### Агент CLI (`hyper-node`)

```text
hyper-node key setup [KEY] [--plain]             задать ключ API. Без KEY генерируется случайный.
                                                  по умолчанию создаётся ключ со встроенным отпечатком сертификата (для TLS);
                                                  --plain создаёт обычный ключ (для non-TLS)
hyper-node key show                              показать ключ API (с форматом отпечатка сертификата)
hyper-node cert gen                              создать/обновить TLS-сертификат (самоподписанный, в /etc/hyper-node/)
hyper-node cert show                             показать SHA256 отпечаток сертификата
hyper-node mode [tls|plain]                      просмотр / смена режима (tls=шифр. / plain=открытый, после рестарта)
hyper-node serve [--port N] [--no-tls]           запустить агент, по умолч. HTTPS (авто-генерация сертификата)
                                                  слушает 0.0.0.0:5000; --no-tls открытый режим
hyper-node log retention N                       срок хранения логов (по умолч. 7, автоочистка)
hyper-node log show                              показать настройки логов
hyper-node trust add <отпечаток>                 доверять отпечатку сертификата панели (mTLS)
hyper-node trust list                            список доверенных отпечатков
hyper-node trust clear                           очистить все доверенные отпечатки
hyper-node help                                  справка
```

## Архитектура

```
┌────────────────────────────────────────────────┐
│ Отслеживаемые машины                           │
│  hyper-node (агент, порт 5000)                 │
│  ├─ системные данные: CPU/память/темп/диск/    │
│  │   сеть/процессы/логи/порты                  │
│  ├─ аутентификация Bearer key                  │
│  ├─ TLS: самоподписанный сертификат + mTLS     │
│  └─ axum API (HTTPS по умолчанию)              │
└───────────────┬────────────────────────────────┘
                │ HTTPS/mTLS + Bearer key (или открытый режим во внутр. сети)
┌───────────────▼────────────────────────────────┐
│ Сервер (VPS, ...)                │
│  hyper-panel (агрегатор, порт 8088)            │
│  ├─ poller: снимок → параллельная выборка →    │
│  │   запись (22 узла за ~35 мс)                │
│  ├─ пул keep-alive соединений                  │
│  ├─ TLS-клиент: TOFU пиннинг + клиентский      │
│  │   сертификат для mTLS                       │
│  ├─ многопользовательская аутентификация       │
│  ├─ управление узлами: CRUD/rename/ping/логи/  │
│  │   перезагрузка/выключение                   │
│  └─ проверка протокола при добавлении          │
└────────────────────────────────────────────────┘
```

> **HTTP панели сам по себе не шифруется (TLS)** — не выставляйте его напрямую в интернет.
> Для удалённого доступа используйте HTTPS reverse proxy (Caddy/Nginx) или частную сеть (Tailscale).

## Модель безопасности

| Уровень | Механизм |
|---|---|
| Транспорт | TLS 1.3 (rustls), самоподписанный сертификат (10 лет) |
| Идентичность сервера | Пиннинг отпечатка сертификата (TOFU, далее фиксировано) |
| Идентичность клиента | Взаимный TLS опционален — добавьте отпечаток сертификата панели (`hyper-node trust add`), чтобы включить mTLS |
| Приложение | Bearer API ключ на узел |
| Изоляция процессов | hyper-panel работает под выделенным не-root пользователем (hyperscope); hyper-node — под root |
| Аутентификация панели | HttpOnly cookie (1 день), солевые хеши, единый 401 |

Отпечаток сертификата узла встроен в ключ (`ключ|SHA256:отпечаток`) — вставка полного ключа
в панель автоматически включает TLS и пиннинг.

## Пути конфигурации

- Панель: `/etc/hyper-panel/` — `nodes.json`, `auth.json`, `panel.json`, клиентский сертификат; логи в `/var/log/hyper-panel/`
- Агент: `/etc/hyper-node/` — `key`, `cert.pem`, `key.pem`, `trust.json`, `mode`; логи в `/var/log/hyper-node/`

## Примечания

- Узлы слушают порт `5000` по умолчанию. В публичных сетях используйте TLS (по умолчанию) или
  Tailscale — открытый режим можно перехватить.
- Смените пароль администратора по умолчанию (`admin`/`admin`) сразу после первого входа.
- Для второй панели с взаимным TLS добавьте отпечаток её клиентского сертификата на каждом узле:
  `hyper-node trust add <SHA256:отпечаток>` (сертификат панели авто-генерируется в
  `/etc/hyper-panel/client-cert.pem`).
